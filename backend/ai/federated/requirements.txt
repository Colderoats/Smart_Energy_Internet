# Module 4 (federated learning) — its OWN virtualenv: backend/ai/federated/venv
#
# Why a separate venv: Flower 1.38 hard-pins fastapi 0.138 / uvicorn 0.49 /
# starlette 1.3 / protobuf<7, which conflicts with backend/venv (fastapi 0.115.6,
# protobuf 7.x). Installing it there would silently upgrade the Module 1-3 stack.
# The backend itself does NOT need Flower: the final federated model is exported
# in Module 3's artifact format and loaded with plain torch.
#
# Ray-based Flower simulation is NOT installable here (flwr[simulation] pulls Ray
# only on non-Windows for Python >= 3.13), so the federation runs as a Flower
# gRPC server + one client PROCESS per grid node on localhost.
--extra-index-url https://download.pytorch.org/whl/cpu
torch==2.14.0
torch_geometric==2.8.0.post1
flwr==1.38.0
